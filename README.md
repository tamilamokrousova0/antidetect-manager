# Antidetect Manager

Менеджер браузерных профилей для macOS (Apple Silicon) поверх [Camoufox](https://github.com/daijro/camoufox) — Firefox с подменой отпечатка на уровне C++.
У каждого профиля свой закреплённый отпечаток, свой прокси (SOCKS5 с логином или HTTP), свои куки и вкладки.

## Установка на Mac

Нужен Mac на Apple Silicon (M1 и новее).

1. Скачать `Antidetect-Manager-<версия>-arm64.dmg` из [Releases](https://github.com/tamilamokrousova0/antidetect-manager/releases), открыть и перетащить приложение в «Программы».
2. Снять карантин (приложение не подписано Apple Developer ID, иначе macOS скажет «повреждено» или «не удаётся проверить разработчика»):
   ```sh
   xattr -dr com.apple.quarantine "/Applications/Antidetect Manager.app"
   ```
   Альтернатива без терминала: запустить, в «Системные настройки → Конфиденциальность и безопасность» нажать «Открыть всё равно».
3. При первом запуске приложение предложит скачать движок браузера (Camoufox, ~1.3 ГБ) в `~/Library/Caches/camoufox` — один раз.

Приложение самодостаточно: внутри свой Python и все зависимости, папка проекта, Homebrew и uv не нужны.
Данные профилей: `~/Library/Application Support/antidetect-manager/` (`ADM_DATA_DIR` переопределяет); папка каждого профиля называется как профиль (`profiles/pp_004/`), при переименовании папка переименовывается на следующем запуске, недопустимые для файловой системы символы заменяются на `_`, одинаковые имена получают суффикс `-<id>`. Логи приложения: `~/Library/Application Support/Antidetect Manager/logs/` (Windows: `%APPDATA%\Antidetect Manager\logs\`). Требуется macOS 15+ (колёса зависимостей движка собраны под него).

### Windows (x64)

Сборка есть: `Antidetect-Manager-Setup-<версия>-win-x64.exe` (установщик) и `-win-x64.zip` (распаковать и запустить) из того же Releases. Движок Camoufox скачивается при первом запуске в `%LOCALAPPDATA%\camoufox`, данные профилей — `%LOCALAPPDATA%\antidetect-manager`. Без сертификата SmartScreen покажет «неизвестный издатель»: «Подробнее → Выполнить в любом случае». Статус: собирается с Mac кросс-сборкой (python-build-standalone + колёса под Windows через uv), на реальной Windows ещё не прогонялось — см. «Что проверить на Windows» ниже.

### Из исходников (для разработки)

```sh
git clone https://github.com/tamilamokrousova0/antidetect-manager ~/Documents/Claude/antidetect-manager
cd ~/Documents/Claude/antidetect-manager
./setup.sh
```
`setup.sh` ставит `uv` и `node` (если их нет), Python-окружение с Camoufox, сам браузер, собирает приложение в `/Applications` и добавляет его в Dock.

Сборка дистрибутива: `cd ui && npm run bundle && npm run dist:dmg` → `ui/dist/*.dmg` и `*.zip`; Windows с Mac: `npm run bundle:win && npm run dist:win` → `Setup-*.exe` и `*-win-x64.zip` (нужны `brew install makensis wine`: makensis electron-builder'а только x86_64, `build/dist-win.js` подставляет нативный из Homebrew через `ELECTRON_BUILDER_NSIS_DIR`). Бандл Python + пакеты собирает `ui/build/make-bundle.js` (python-build-standalone + `uv pip install --python-platform`), подпись ad-hoc на macOS в `ui/build/afterpack.js`.

**Что проверить на Windows** (кросс-сборка не запускалась вживую): первый запуск и скачивание движка; запуск профиля и кнопка «Закрыть» (остановка идёт через stdin-команду `stop`, SIGTERM на Windows нет); закрытие последнего окна; список шрифтов хоста (PowerShell `InstalledFontCollection`); патч `distribution/policies.json` в папке движка; сохранение паролей; заголовок окна с именем профиля.

## Использование

Приложение: список профилей, поиск/фильтр по тегам, создание пачкой, проверка прокси, запуск/закрытие, карточка профиля (прокси, теги, заметки, язык, cookies).
Горячие клавиши: ⌘N — новый профиль, ⌘F — поиск, Esc — закрыть карточку.

То же из терминала (`--json` у всех команд):
```sh
./adm.sh create acc --count 20 --proxy 'host:port:user:pass' --tags fb,de
./adm.sh list [--tag fb]
./adm.sh check all                       # перепроверить прокси
./adm.sh check-proxy 'socks5://u:p@h:port'
./adm.sh set acc-001 --proxy '...' --locale en-US --status active   # --proxy '' убрать, --locale '' авто; статусы warmup|active|checkpoint|banned
./adm.sh launch acc-001 [--url https://...]
./adm.sh cookies-import acc-001 cookies.json [--replace]   # JSON или cookies.txt, '-' = stdin
./adm.sh cookies-export acc-001 [--format netscape] [-o file]
./adm.sh delete acc-001
```
Форматы прокси: `host:port:user:pass`, `socks5://user:pass@host:port`, `user:pass@host:port`, `http://user:pass@host:port`.

## Обновление движка

```sh
./update-engine.sh --check     # есть ли новая стабильная версия
./update-engine.sh             # обновить (профили закрыть)
./update-engine.sh --to 0.5.8  # поставить конкретную версию / откатиться
./update-engine.sh --beta      # следить за пре-релизами (с 27.10 движок живёт на бета-канале)
```
По умолчанию берутся стабильные релизы с PyPI; `--beta` (и канал «бета» в настройках приложения) считает и пре-релизы: Camoufox выпускает исправления детекта сначала туда (релизный поезд два раза в месяц; например, hCaptcha узнавала любой Camoufox по `new Worker("chrome://juggler/…")` до 0.5.9b1). пакет обновляется вместе с «парной» сборкой браузера, после — пробный запуск, при сбое — автооткат. Старые сборки остаются в `~/Library/Caches/camoufox/browsers/`.

Еженедельная проверка с уведомлением (пн 11:00; Telegram через `claw-send`, если он есть, иначе уведомление macOS):
```sh
scripts/install-engine-watch.sh
```

## Как устроено

| | |
|---|---|
| `adm/store.py` | SQLite + папка на профиль (имя папки = имя профиля, `sync_dir` при list/launch/rename; старые папки-id мигрируют сами) |
| `adm/proxy.py` | парсинг прокси, проверка exit IP / гео через цепочку провайдеров: ip-api.com → ipwho.is → ipinfo.io (HTTPS через PySocks); различает «прокси мёртв» и «гео-сервис недоступен» |
| `adm/socks_forward.py` | локальный форвардер для всех прокси: браузер → 127.0.0.1 SOCKS5 без авторизации → апстрим SOCKS5 или HTTP CONNECT с логином; DNS на стороне прокси; детектор падения прокси (on_state) |
| `adm/launcher.py` | запуск: проверка прокси (без неё не стартует), geoip → таймзона/геолокация/WebRTC-IP, язык, восстановление сессии |
| `adm/cookies.py` | импорт/экспорт cookies в фоновой сессии без сети |
| `adm/pdl.py` | многопоточная загрузка больших файлов с GitHub |
| `adm/cli.py` | CLI |
| `ui/` | Electron 45: `main.js` запускает встроенный Python (`<resources>/adm/python`, в dev — `.venv`) с `-m adm.cli --json`, каждый открытый профиль — отдельный процесс, остановка — строка `stop` в stdin (+ SIGTERM вне Windows); экран первого запуска качает движок (`adm engine status/fetch`) |
| `scripts/` | обновление движка, загрузка браузера, сторож обновлений, `live_check.py` |
| `tests/` | `test_forwarder.py`, `test_forwarder_state.py`, `test_cookies.py`, `test_proxy_geo.py` (без браузера), `e2e_launch.py`, `socks_server.py` (тестовый SOCKS5 с логином) |

## Что закреплено за профилем

- **Отпечаток** генерируется один раз (статистика реальных устройств) и хранится в профиле: платформа, экран, GPU, шрифты, медиа-устройства, голоса, аудио — одинаковые от запуска к запуску. Версия Firefox в UA всегда равна версии установленного движка.
- **Язык** — основной официальный язык страны прокси (DE→de-DE, BE→nl-BE), меняется только при смене страны; можно задать вручную.
- **По IP прокси при каждом запуске**: таймзона, геолокация, IP в WebRTC.
- **Логи**: stdout/stderr каждого запуска профиля пишется в `logs/profile-<id>.log` в userData приложения («Antidetect Manager», не папка данных профилей) (кнопка «Лог запуска» в карточке), скачивание движка — в `logs/engine-fetch.log` (Настройки → «Папка логов»). При ошибке запуска строка статуса показывает последнюю строку, полный текст — в логе.
- **Самопроверка после запуска**: через пару секунд после старта лаунчер изнутри браузера читает WebRTC-кандидаты, язык и таймзону и сверяет с прокси, плюс делает запрос к IPv6-only хосту (`api6.ipify.org`): профиль за прокси должен выглядеть как IPv4-сеть, а если ответ пришёл и совпал с публичным IPv6 этого компьютера — это утечка (красный). Результат — точка у колонки «Выход» (зелёная / жёлтая: таймзона браузера не совпала с гео провайдера / красная: WebRTC отдаёт не IP прокси или язык не тот) и блок «Самопроверка» в карточке. Хранится в `self_check` профиля; событие `{"event":"selfcheck"}` в stdout лаунчера.
- **Паспорт профиля**: в карточке после первого запуска показывается то, что реально увидел сайт (UA, платформа, экран, ядра, GPU, языки, таймзона, WebRTC-IP), до запуска — оценка по отпечатку.
- **Статус профиля**: прогрев / рабочий / чекпоинт / бан — цветная точка перед именем, фильтр в тулбаре, `--status` в CLI. Фиксированный набор, чтобы не расползался как теги.
- **Падение прокси посреди сессии**: все прокси идут через локальный форвардер (SOCKS5 и HTTP CONNECT апстрим), и после двух подряд неудачных подключений к апстриму он сообщает `{"event":"proxy","state":"down"}` → кнопка профиля краснеет («Прокси ✕»), при первом удачном соединении — `up`. Побочный плюс: браузер никогда не видит логин/пароль прокси, DNS всегда на стороне прокси.
- **Языки**: к основному языку страны добавляется английский как у настоящих пользователей: `de-DE,de,en-US,en` в `navigator.languages` и Accept-Language. Ручной locale со списком через запятую не трогается.
- **Сессия**: вкладки и сессионные cookies восстанавливаются между запусками, как в обычном браузере. Закрытие последнего окна браузера (⌘W / красная кнопка) = закрытие профиля: без этого Firefox на macOS остаётся жить без окон, профиль висит «запущен», а клик по Dock открывает пустое окно. Так как закрытому окну нечего восстанавливать, адреса вкладок запоминаются в `last_tabs.json` профиля и открываются при следующем запуске.
- **Панель инструментов**: «+» новой вкладки и список вкладок — в полосе вкладок, как в обычном Firefox (на Camoufox 156 кнопка уезжала в правый угол nav-bar и полоса вкладок её не принимала; на 158 принимает). Из nav-bar убраны две «пружины» (пустые промежутки справа от адресной строки), кнопка Firefox-аккаунта и «элементы закладок». Новый профиль не трогается (дефолт 158 уже такой), профиль с сохранённой раскладкой переписывается один раз (маркер `.toolbar-v2`), дальнейшая ручная настройка панели не трогается.
- **Геолокация**: координаты подставляет Camoufox по гео прокси внутри сетевого провайдера; системные провайдеры (CoreLocation / Windows Location / GeoClue) выключены и `geo.prompt.open_system_prefs=false` — иначе Firefox при запросе сайта лез в «Службы геолокации» macOS и открывал Системные настройки. Проверено: `getCurrentPosition` возвращает точку рядом с городом прокси, настройки не открываются.
- **Имя профиля в окне**: заголовок окна начинается с имени профиля («FB Anna — Facebook»). Делает крошечное расширение на профиль (`badge-addon/` в папке профиля, `windows.update({titlePreface})`), страница этого не видит; заголовок показывается нативной полосой над вкладками (`browser.tabs.inTitlebar = 0`). userChrome.css Camoufox не грузит.
- **Без OS-аутентификации паролей**: Firefox 127+ при автозаполнении и открытии about:logins просит Touch ID / пароль macOS (Windows Hello) и лезет в системное хранилище ключей (диалог «хочет получить доступ к системным настройкам хранения паролей»). Выключено через `signon.management.page.os-auth.locked.enabled=false` + инвертированные legacy-prefs `extensions.formautofill.reauth.enabled` / `signon.management.page.os-auth.enabled` (миграция 146 выводит новый locked-pref из них). Проверено: в свежем профиле и в профиле с уже включённой OS-auth `LoginHelper.getOSAuthEnabled()` = false. Также убраны подсказки «импортировать пароли из другого браузера» и проверки утечек паролей.
- **Пароли**: штатный менеджер паролей Firefox включён — при первом входе (Facebook, Google, …) браузер предлагает сохранить логин, в следующий раз подставляет его в форму; хранится зашифрованно в папке профиля (`logins.db` + `key4.db`), список — `about:logins`. Автоматического нажатия «Войти» нет намеренно: автологин скриптом на FB/Google — верный способ словить чекпоинт.

## Решения и ловушки

- Canvas меняется от сессии к сессии — это штатная защита Firefox (`privacy.baselineFingerprintingProtection`). Не выключать: без неё у всех профилей на одном Mac одинаковый canvas железа.
- На macOS-хосте выбирать отпечаток macOS — тогда шрифты настоящие системные. Лаунчер передаёт Camoufox allow-list из реальных семейств хоста (`NSFontManager`) + каталог Camoufox: без этого Camoufox показывает только «базу» macOS и прячет настоящие шрифты (Herculanum, SignPainter, Kefa III, Marion), отличаясь от обычного Firefox на той же машине.
- Pixelscan «Masking detected» на macOS 27: их эталонный список шрифтов Mac требует Rockwell, который macOS 27 резолвит по имени, но не перечисляет (скрыт из enumeration, копия в `~/Library/Fonts` не помогает). Обычный Firefox 158 на том же Mac получает тот же вердикт; остальные 11 признаков их проверки (UA/заголовки, WebGL, платформа, локаль, железо, canvas) у профиля чистые. С прокси карточки «Timezone spoofed» / «Proxy detected» зелёные.
- Проверка прокси читает ровно один HTTP-ответ (по Content-Length / chunked), а не до EOF: часть прокси игнорирует `Connection: close` и держит туннель, из-за чего рабочий прокси раньше считался мёртвым (таймаут 30 с).
- GPU у mac-профилей «Apple M1, or similar» — так настоящий Firefox показывает любой Apple Silicon.
- Импорт/экспорт cookies — только у закрытого профиля. Сессионные cookies при импорте получают срок 30 дней. Фоновая сессия ждёт ~3 с восстановления сессии: если закрыть раньше, Firefox сохранит пустую сессию.
- Прокси не прошёл проверку → профиль не запускается (иначе сайт увидел бы реальный IP). Но если прокси отвечает, а недоступны сами гео-сервисы (все три), профиль стартует с гео из прошлой удачной проверки: в таблице у выхода появляется метка «кэш», в stderr — warning. Без прошлой проверки запуск всё равно блокируется (таймзону подставить нечем). `ADM_GEO_PROVIDERS=ipwho.is,ipinfo.io` переопределяет порядок провайдеров (тесты, обход лимита ip-api 45 запросов/мин).
- Сетевой отпечаток выхода (TCP/IP: ОС, MTU) — свойство прокси, браузером не исправляется.
- launchd не может запускать файлы из `~/Documents` (TCC) — поэтому сторож обновлений копируется в `~/.local/var/`.
- Camoufox выключает менеджер паролей не только prefs, но и корпоративной политикой `PasswordManagerEnabled: false` в `Camoufox.app/Contents/Resources/distribution/policies.json` (пref становится locked). `adm engine patch` убирает `PasswordManagerEnabled` / `OfferToSaveLogins` / `DisableFormHistory` (вызывается после `engine fetch` и перед каждым запуском; оригинал — `policies.json.orig`). Бандл Camoufox только linker-signed, без печати ресурсов, поэтому правка не ломает запуск.
- Сборка бандла: НЕ передавать uv глобальный `--prerelease=allow` — он тянет пре-релизы всех зависимостей (в 0.2.3 так приехал httpx 1.0.dev без `httpx.get`, и профили не запускались); пин `camoufox==0.5.9b5` в requirements.txt uv принимает и так. Для хост-платформы бандл резолвится самим встроенным интерпретатором (`--python`), иначе uv считает macOS старым и берёт колесо indexed_zstd без zstd-символов.
- .app без Developer ID: подпись ad-hoc (`codesign --sign -`), иначе Apple Silicon не запускает изменённый бандл; Gatekeeper у скачавшего всё равно требует снять карантин. Python внутри — python-build-standalone из uv (переносимый), пакеты через `pip --target`, без venv (venv не переносится).

## Проверка профиля на сайтах

```sh
PYTHONPATH=. .venv/bin/python scripts/live_check.py <профиль> [папка]
```
BrowserLeaks (IP / WebRTC / DNS), CreepJS, Pixelscan, SannyBot — скриншоты и текст в папку (по умолчанию `/tmp/adm-live-check`). Откроется окно браузера.
